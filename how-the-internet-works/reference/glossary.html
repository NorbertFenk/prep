Glossary — How the Internet Works

Terms used across all lessons. One line each — interview-answer length.

DNS (Domain Name System)
The internet's phonebook: translates domain names (google.com) into IP addresses.
IP address
A numeric address identifying a device on a network, e.g. 142.250.80.46. Traffic is routed by IP, not by name.
Packet
A chunk of data plus a header (source, destination). All internet traffic is broken into packets.
TCP (Transmission Control Protocol)
Connection-oriented transport: reliable, ordered delivery. Opens with a 3-way handshake: SYN, SYN-ACK, ACK.
UDP (User Datagram Protocol)
Connectionless transport: fast, no guarantees, no handshake. Used by DNS queries, video, games.
TLS (Transport Layer Security)
Encryption + authentication layer on top of TCP. The "S" in HTTPS: verifies the server's certificate, then agrees a shared key.
HTTP (HyperText Transfer Protocol)
Request/response protocol of the web: client sends GET /path, server replies with a status code and content.
HTTPS
HTTP inside a TLS-encrypted connection. Default port 443 (plain HTTP: 80).
URL (Uniform Resource Locator)
Full address of a resource: scheme + host + path, e.g. https://google.com/search.
Port
A number (0–65535) identifying which service on a machine should receive traffic. 443 = HTTPS, 80 = HTTP, 53 = DNS.
Handshake
An opening exchange to establish a connection. TCP: 3 packets. TLS: negotiates encryption after TCP is up.
Resolver (recursive resolver)
The server (usually your ISP's) that chases down a DNS answer for you: root → TLD → authoritative nameserver.
ISP (Internet Service Provider)
The company connecting you to the internet; typically provides your DNS resolver by default.
CDN (Content Delivery Network)
Globally distributed servers that cache content near users. Your "google.com" request usually hits a CDN edge, not one central server.
Root nameserver
Top of the DNS hierarchy. Doesn't know IPs — it points you at the right TLD server.
TLD (Top-Level Domain)
The last part of a domain: .com, .org, .dev. TLD servers point to the domain's own nameservers.
Authoritative nameserver
The DNS server that actually holds a domain's records and gives the final answer. End of the lookup chain.
A record / AAAA record
DNS records mapping a name to an IPv4 (A) or IPv6 (AAAA) address.
CNAME record
DNS alias: points a name at another name instead of an IP. Costs an extra lookup.
TTL (Time To Live)
How long a record may be cached before re-fetching, in seconds. Why DNS changes "propagate" slowly.
Sequence number
Per-byte counter in every TCP segment. Lets the receiver order segments, detect loss and duplicates.
Flow control
Receiver advertises its buffer space so the sender doesn't overwhelm it.
Congestion control
Sender slows down when it detects loss/delay, protecting the network from itself.
RTT (Round-Trip Time)
Time for a packet to go somewhere and come back. Every handshake costs at least one RTT.
Asymmetric encryption
Public/private key pair: encrypt with the public key, only the private key can decrypt. Slow — used only to bootstrap.
Symmetric encryption
Both sides share one secret key. Fast — carries all the actual TLS traffic.
Certificate
Signed document binding a domain name to a server's public key. Proves "this key really is google.com's".
CA (Certificate Authority)
Trusted third party that signs certificates. Browsers ship with ~150 root CAs they already trust.
Method (HTTP method/verb)
What the request asks for: GET reads, POST creates, PUT replaces, DELETE removes. First word of the request line.
Status code
The server's one-word answer: 2xx success, 3xx redirect, 4xx client error (404), 5xx server error (500).
Header
A Name: value metadata line in a request or response — Host, Cookie, Content-Type, Cache-Control.
Cookie
A token the server sets (Set-Cookie) and the browser echoes back on every later request — how stateless HTTP remembers you.
Idempotent
Repeating the request leaves the server in the same state. GET/PUT/DELETE are; POST isn't — retrying it may act twice.
DOM (Document Object Model)
The HTML document parsed into a tree of nodes. JavaScript's interface to the page.
CSSOM (CSS Object Model)
All the page's CSS parsed into a structure the browser can apply. Building it blocks painting.
Render tree
DOM + CSSOM merged, keeping only visible nodes. The input to layout.
Layout (reflow)
Computes exact position and size of every element. Geometry changes force it to run again — expensive.
Paint
Filling in pixels for the laid-out elements, then compositing layers into what you see.
Critical rendering path
The sequence from bytes to pixels: DOM, CSSOM, render tree, layout, paint. Fewer blocking resources = faster first paint.
Browser cache
Local store of past responses. Freshness and revalidation are controlled by response headers — the fastest request is the one never sent.
Cache-Control
Response header defining cache rules: max-age=N (fresh for N seconds), no-store (never cache).
ETag
A version fingerprint for a resource. The browser sends it back (If-None-Match) to ask "changed?" — unchanged gets 304 Not Modified, headers only.
Compression (Content-Encoding)
Lossless shrinking of responses (brotli/gzip) — 70–80% for HTML/CSS/JS. Negotiated via Accept-Encoding; don't re-compress already-compressed media.
Resource waterfall
The devtools view of every request as a bar (DNS, handshake, TTFB, download) — how you see where the time actually goes.
TTFB (Time To First Byte)
Time from sending the request to receiving the first byte: network round trip plus the server's own processing.
Reverse proxy
Server that sits in front of web servers and forwards client requests to them — clients never touch the origins directly. Adds TLS termination, caching, hiding of origin IPs.
Forward proxy
Proxy that sits in front of clients (VPN, corporate filter) and hides them from servers. A reverse proxy does the mirror-image job for servers.
Load balancer
Reverse proxy that spreads traffic across a pool of interchangeable servers using an algorithm, and stops sending traffic to servers that fail health checks.
Round robin
Simplest load-balancing algorithm: each new request goes to the next server in the list.
Health check
Periodic probe the load balancer runs against each server; failing servers are pulled from rotation until they recover.
Failover
Automatic rerouting of traffic away from a failed server to healthy ones — the reason losing one machine isn't an outage.
Multiplexing (HTTP/2)
Many request/response exchanges interleaved as frames over one TCP connection; frame tags say which stream each belongs to.
Stream
One independent request/response exchange inside a connection, tracked by a stream ID — the unit HTTP/2 schedules and prioritizes.
Head-of-line blocking
One stalled item delaying everything behind it. HTTP/2 fixed the HTTP-layer kind; QUIC fixed the TCP-layer kind with independent streams.
HPACK
HTTP/2 header compression: Huffman coding plus static/dynamic lookup tables turn repeated headers into tiny indexes.
QUIC
UDP-based transport beneath HTTP/3: reliable streams, built-in TLS 1.3, no cross-stream blocking, encrypted by default, migrates between networks.
0-RTT
Resumed QUIC sessions send request data in the very first flight of packets, using cached session keys — zero waiting round trips.
Connection ID (connection migration)
QUIC names connections by ID rather than IP:port, so a device changing networks keeps its downloads alive.
Latency
Time a round trip takes; set mostly by distance and light speed in fiber (~200 km/ms) — the thing CDNs exist to shrink.
Origin server
Where content genuinely lives; users behind a CDN normally never touch it directly.
Edge (PoP)
Data center near users holding cached copies — a reverse proxy plus a cache, deployed worldwide.
Anycast
One IP announced from many sites; routing delivers to the nearest, and failure or overload reroutes to the next closest.
