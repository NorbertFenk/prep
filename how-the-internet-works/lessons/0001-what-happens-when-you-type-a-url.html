How the Internet Works / Lesson 1

What happens when you type google.com and press Enter?

This is the classic networking interview question. Your goal by the end of this lesson: answer it out loud, in order, in about 60 seconds — without notes.

~15 min

The 7-step journey

1
Browser parses the URL

Splits https://google.com/ into scheme (https), host (google.com), path (/). If what you typed isn't a URL, it becomes a search query instead.

2
DNS lookup: name → IP address

Machines route by IP, not names. The browser checks its cache, then the OS cache, then asks a recursive resolver (usually your ISP's), which walks root → .com TLD → Google's authoritative nameserver to get an IP like 142.250.80.46.

3
TCP connection: the 3-way handshake

Browser opens a TCP connection to that IP on port 443 (the HTTPS default). Three packets establish it: client sends SYN, server replies SYN-ACK, client confirms ACK.

4
TLS handshake: turn on encryption

On top of the open TCP connection, browser and server agree on TLS version and ciphers. The server presents its certificate (proving it really is Google, signed by a Certificate Authority), and both sides derive a shared encryption key.

5
HTTP request

Now encrypted, the browser sends GET / HTTP/1.1 with a Host: google.com header (plus cookies, user-agent, and friends).

6
Server responds

Usually a CDN edge server or load balancer receives it, routes to a backend, and returns 200 OK with the HTML (or 304 Not Modified if your cache is fresh).

7
Browser renders — and repeats

The browser parses HTML into the DOM, applies CSS, runs JS. Every referenced asset (images, fonts, scripts) triggers its own request — and assets on other domains restart the whole journey from step 2.

Check yourself (instant feedback)

1. What's the very first thing the browser does after you press Enter?

2. What problem does DNS solve?

3. Which comes first: the TCP handshake or the TLS handshake?

4. What are the three packets of the TCP handshake, in order?

5. The Google HTML loads a font from fonts.gstatic.com. What happens?

The real skill: say it out loud

Interviews are spoken. Set a 60-second timer and explain the whole journey out loud, from Enter key to rendered page. Then compare against the model answer.

Model 60-second answer (peek only after trying)

"First the browser parses the URL to get the scheme, host, and path. Then it resolves the host via DNS — checking caches first, then asking a recursive resolver which walks the root, TLD, and authoritative nameservers — to get an IP address. It opens a TCP connection to that IP on port 443 with a three-way handshake: SYN, SYN-ACK, ACK. On top of that it does a TLS handshake: the server presents its certificate to prove its identity, and they agree on encryption keys. Only then does the browser send the HTTP request — a GET for the path. The server responds with the HTML, and the browser parses and renders it, firing off more requests for any sub-resources — repeating DNS, TCP, and TLS for any new origins."
