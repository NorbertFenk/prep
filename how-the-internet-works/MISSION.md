# Mission: How the Internet Works

## Why
Preparing for technical interviews (SWE/DevOps/SRE) where networking questions come up. The user codes but the layers under the code — DNS, TCP, TLS, HTTP — are foggy. Goal: answer networking interview questions confidently and correctly.

## Success looks like
- Deliver a fluent 60-second answer to "what happens when you type google.com and press Enter"
- Explain DNS resolution, TCP vs UDP, TLS handshake, and HTTP request/response without notes
- Handle follow-ups ("why TLS after TCP?", "what port?", "what if the packet is dropped?") without freezing

## Constraints
- Learns via short interactive lessons; already codes, so analogies to code are fine
- Interview-focused: depth where interviews probe, breadth elsewhere

## Out of scope
- Socket programming / writing network code (Beej's-guide territory)
- Deep BGP/routing internals, network hardware config
- Browser rendering engine internals beyond a high-level pass
