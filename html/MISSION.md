# Mission: HTML

## Why
The user codes (Go, knows the HTTP request/response cycle) but writes web markup by imitation — copy-pasted div soup that works but can't be explained. HTML is the layer underneath every web tool they've built. Goal: read, write, and validate clean semantic HTML; explain in interviews why structure (semantics, accessibility, the head) matters, not just how to make pixels appear.

## Success looks like
- Write a complete, valid, semantic page — headings, lists, links, images, tables, forms — without copying a template
- Justify every element choice: "this is a `<section>` because…", "this `<div>` is honest because nothing better exists"
- Fix broken markup using the W3C validator and browser devtools instead of trial and error
- Answer follow-ups confidently: "semantic vs presentational?", "why does alt matter?", "what does the browser do with invalid HTML?"

## Constraints
- Self-paced, short interactive lessons (house style, established over 33 prior lessons)
- Multiple-choice quizzes preferred (assets/quiz.js)
- Uses the web platform itself as the feedback loop — save file, refresh browser, see result

## Out of scope
- CSS layout and JavaScript beyond how they attach to HTML (`<link>`, `<script defer>`)
- Server-side rendering, frameworks, build tools
- SVG drawing techniques beyond embedding basics
