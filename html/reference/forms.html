HTML quick reference

Forms

How the user speaks back: controls, labels, and validation — all semantics.

Anatomy

<form action="/submit" method="get">
  <label for="name">Name (required):</label>
  <input type="text" name="name" id="name" required />
  <button>Submit</button>
</form>
AttributeFor
action · methodWhere submission goes · how (get puts data in the URL as query params).
typePicks the control (see below).
nameNames the data item submitted — name=Bob. Radios in a set share it.
idLinks the control to its <label for>.
valueWhat gets submitted (radios/checkboxes/options); pre-fills text fields.
checked · disabledPre-selected · unselectable.

Controls

ControlRule of thumb
<input type="text|email|url|tel|password|number|color">Typed inputs validate their format for free.
<input type="radio">One of a set: shared name, per-option value.
<input type="checkbox">Any number: separate name per checkbox.
<select>/<option>/<optgroup>Drop-down; optgroup label groups options.
<textarea rows cols>Multi-line; its content is its value.
<fieldset>+<legend>Names a group of controls — announced by screen readers.

Labels — the contract

Explicit: <label for="x"> ↔ id="x". Buys: screen readers announce the label at the control; clicking the label focuses the control (bigger hit area). Prefer explicit over nesting the input inside the label.

Validation attributes

AttributeEffect
requiredBlocks submission when empty.
minlength/maxlengthLength bounds.
min/maxNumeric bounds.

Client-side validation is UX; server-side validation is security. Never trust what the client sends.

Buttons

TypeBehavior
<button> (default: submit)Submits the form.
type="button"Nothing without JavaScript.
type="reset"Wipes the form — avoid; it destroys people's work.

Use <button>, not legacy <input type="submit">.
