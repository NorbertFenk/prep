HTML quick reference

Validation & workflow

HTML has no syntax errors — the browser silently fixes your markup. These two tools tell you what it actually built.

The loop

  1. Edit → save → refresh browser → look. The entire dev cycle for static HTML.
  2. Suspect something? Open devtools (F12) → Inspector/Elements tab: the rendered DOM, not your source. Hover nodes to highlight them in the viewport.
  3. Before shipping: validator.w3.org → Validate by Direct Input → Check. Done when the green banner says "No errors or warnings to show."

Common validator messages decoded

MessageReally means
"End tag li implied, but there were open elements"A missing close tag — the end tag was guessed, not present.
"Unclosed element strong"Exactly what it says; everything after it is bold.
"End tag strong violates nesting rules"Overlapping tags — close in reverse order.
"End of file reached when inside an attribute value"An unterminated quote swallowed the rest of the document. The browser deleted the element entirely.
"End of file seen and there were open elements"Something never closed — often caused by that same missing quote.

One broken tag cascades into a dozen errors. Fix the first few, revalidate, repeat.

What the browser fixes (and how)

Your mistakeBrowser's guess
Unclosed <p>/<li>Usually closed correctly — which is why the habit forms.
Unclosed <strong>Bolds the rest of the document, block by block.
Badly nested <strong><em>…</strong></em>Untangles into valid (but maybe unintended) nesting.
Missing attribute quoteMay delete the element entirely — the most invisible failure.
