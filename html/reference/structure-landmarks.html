HTML quick reference

Structure & landmarks

The semantic page skeleton — what screen readers navigate by.

The landmarks

<header>  — intro content: global (child of body) or per-article
<nav>     — the main navigation only; secondary links stay out
<main>    — unique content of THIS page: exactly one, in body directly
  <article> — self-contained: makes sense on its own (post, card)
  <section> — thematic grouping; begin it with a heading
  <aside>   — tangential: related links, author bio
<footer>  — end content: fine print, credits, contacts

Decisions

QuestionAnswer
Makes sense on its own, outside the page?<article>
A themed chunk of this page?<section> (+ heading)
Indirectly related content?<aside>
No semantic element fits, need a CSS/JS hook?<div> (block) / <span> (inline) + class — the honest fallback, use sparingly

Why it pays

  • Screen readers list landmarks as a menu: "jump to navigation", "jump to main". Div soup = empty menu = users wade through everything, every page.
  • Search engines weigh headings and structure.
  • Designs change; the structure (and every tool built on it) survives.
