HTML quick reference

Embedding & security

<iframe> puts another page inside yours — the most dangerous element in HTML, and its defenses.

<iframe> essentials

<iframe src="https://www.youtube.com/embed/ID"
        width="100%" height="500"
        allowfullscreen sandbox>
</iframe>
AttributeFor
srcURL of the embedded document (own browsing context).
sandboxWith no value: blocks scripts, forms, popups — everything. Add permissions back one by one. Never combine allow-scripts + allow-same-origin on same-origin content: the frame could remove its own sandbox.
allowfullscreenPermits fullscreen mode.

Threats & defenses

ThreatDefense
Clickjacking: invisible frames steal clickssandbox; serve your own pages with X-Frame-Options/Content-Security-Policy so others can't frame you.
Tampering with embedded content in transitHTTPS everywhere — also keeps embedded and parent documents apart.
Embedding pages that forbid itServers send X-Frame-Options: DENY/CSP frame-ancestors; browsers then refuse — that console error is a feature.
Too much third-party contentRule: embed only when necessary; assume third-party content is dangerous until proven otherwise.

The also-rans

ElementStatus
<embed> / <object>Plugin-era relics (Flash, applets); all cases better served by <iframe>.
FramesetsDead since the 90s; recognize in the wild, never write.
