HTML quick reference

Tables

For tabular data only — never layout. Structure plus scope is what makes them readable by machines.

Skeleton

<table>
  <caption>What this table is</caption>
  <colgroup>
    <col span="2" />
    <col class="highlight" />
  </colgroup>
  <thead>
    <tr><td colspan="2"></td><th scope="col">Name</th></tr>
  </thead>
  <tbody>
    <tr><th scope="row">Mercury</th><td>0.330</td></tr>
  </tbody>
</table>

Building blocks

Element / attributeFor
<tr> / <td> / <th>Row / data cell / header cell (semantic heading, not just bold).
<thead>/<tbody>/<tfoot>Row regions: addressed by screen readers and styling.
<caption>Titles the whole table, visible to all users.
colspan / rowspanCell spans N columns / N rows (group headers).
<colgroup>/<col>Style whole columns structurally, without touching cells.

scope — the accessibility payoff

Value"This header labels…"
scope="col"Its column.
scope="row"Its row.
scope="colgroup"Multiple columns it spans.
scope="rowgroup"Multiple rows it spans.

With headers + scopes, a screen reader announces "Mercury, diameter: 4,879 kilometres" — or reads a whole column at once. Alternative for gnarly tables: id on headers, headers on data cells.

Never for layout

  • Layout tables confuse screen readers (they announce row/column structure that isn't real).
  • They produce tag soup — harder to write, maintain, debug.
  • They don't reflow: not responsive by default.
