Anatomy cheat sheet

The document skeleton, the element anatomy, and the rules that prevent 90% of beginner bugs.

The minimal valid page

<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <title>Page title</title>
  </head>
  <body>
    <p>Visible content.</p>
  </body>
</html>
PartFor
<!doctype html>Historical artifact; must be first line. Shortest valid string.
<html lang="…">Root element; language for search engines and screen readers.
<head>Metadata nobody sees: encoding, title, CSS/JS, icons.
<meta charset="utf-8">Character encoding; any human language renders correctly.
<title>Tab text, bookmark name, search-result headline. Not the <h1>.
<body>All displayed content.

Element anatomy

<p class="note" title="extra info">content</p>
 └┬┘└──┬──┘└──────┬──────┘└──┬──┘└┬┘
opening attributes       content closing
 tag                     (inside)    tag
  • Element = opening tag + content + closing tag. The element is the meaning.
  • Attributes: name="value", space-separated, in the opening tag. Always quote values.
  • Boolean attributes are true by presence alone: disabled, required, controls.

Void elements

<img> · <br> · <meta> · <link> · <input> · <hr> — no content, no closing tag. <script> is not void: it needs </script>.

Rules that prevent most bugs

RuleWhy
Nest, don't overlap: close in reverse orderOverlapping tags make the browser guess; permissive parsing fixes things silently, sometimes wrongly.
Always quote attribute valuestitle=The Mozilla homepage becomes three attributes: title="The" + two booleans.
Don't mix quote typesA stray single quote inside double quotes ends the value early.
Whitespace collapses on renderIndent for readability; <pre> is the only element that keeps it.
