Forms: the user speaks back

Links send users away; forms bring data in. They're half of how users interact with a website — and the place where "semantic" stops being an ideal and starts being measurable in support tickets.

~30 min · prereq: 0003, 0007

The anatomy

<form action="/submit_page" method="get">
  <label for="name">Name (required):</label>
  <input type="text" name="name" id="name" required />
  <button>Submit</button>
</form>
1
<form> — the wrapper

action is where submission goes; method is how (get puts the data in the URL — you'll recognize ?name=Bob&email=bob%40bob.com from the Internet course).

2
<input> — the data items

type picks the control: text, email, password, number, tel, url, color… name names the data item submitted; id links the control to its label; required makes the field mandatory.

3
<label> — the contract

Explicit association: <label for="name"> matches id="name". Screen readers announce the label at each control, and clicking the label focuses the control — a bigger hit area for thumbs. (Implicit labels — nesting the input inside the label — work, but explicit ones are easier to read and more reliably announced.)

4
<button> — the trigger

Inside a form, <button> submits. type="button" does nothing without JavaScript; type="reset" wipes the form — a relic that mostly destroys people's work. Use <button>, not legacy <input type="submit">.

Choosing controls

<!-- radio: exactly one of a named set -->
<fieldset>
  <legend>Choose hotel room type:</legend>
  <input type="radio" id="r1" name="hotel" value="economy" checked />
  <label for="r1">Economy (+$0)</label>
  <input type="radio" id="r2" name="hotel" value="superior" />
  <label for="r2">Superior (+$50)</label>
</fieldset>

<!-- checkbox: any number, each its own name -->
<input type="checkbox" id="yoga" name="yoga" />
<label for="yoga">Yoga (+$10)</label>

<!-- select: drop-down of options -->
<select name="transport" id="transport">
  <option value="">--Please choose an option--</option>
  <option value="plane">Plane</option>
</select>

<!-- textarea: multi-line -->
<textarea id="comments" name="comments" rows="5" cols="33"></textarea>

Radio buttons in a set share one name and each needs a value (submission is hotel=economy). Checkboxes represent separate data items. <fieldset> + <legend> group related controls — the semantically correct way to say "these belong together", which screen readers announce.

Client-side validation

<input type="text" id="uname" name="uname" required minlength="5" maxlength="20" />
<input type="email" id="email" name="email" required />
<input type="tel" id="phone" name="phone" required maxlength="15" />
<textarea id="comment" name="comment" required maxlength="200"></textarea>

Submit with an empty required field and the browser blocks it with an error message — no JavaScript. Typed inputs (email, url) validate their format for free. Remember the two-layer rule: client-side validation is UX, server-side validation is security — never trust what the client sends.

Exercise 1 — the real MDN task (Forms and buttons 1)

Create ID and password inputs with semantic labels and a "Log in" submit button:

<form>
  <ul>
    <li>User ID</li>
    <li>Password</li>
    <li></li>
  </ul>

Show solution 
<form>
  <ul>
    <li>
      <label for="uid">User ID</label>

    </li>
    <li>
      <label for="pwd">Password</label>
      <input type="password" id="pwd" name="pwd" />
    </li>
    <li>

    </li>
  </ul>
</form>

Exercise 2 — the real MDN task (Forms and buttons 6)

Add validation to a support form: all fields mandatory; proper types for email and phone; username 5–20 characters; phone max 15; comment max 200. Submitting should refuse until everything passes:

<form>
  <h2>Enter your support query</h2>
  <ul>
    <li>
      <label for="uname">User name:</label>
      <input type="text" name="uname" id="uname" />
    </li>
    <li>
      <label for="email">Email address:</label>
      <input type="text" name="email" id="email" />
    </li>
    <li>
      <label for="phone">Phone number:</label>
      <input type="text" name="phone" id="phone" />
    </li>
    <li>
      <label for="comment">Comment:</label>
      <textarea name="comment" id="comment"> </textarea>
    </li>
    <li>

    </li>
  </ul>
