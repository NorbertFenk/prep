Functions that know their data

In about ten minutes, you will turn a plain function into a method on your own type — the step that makes structs behave, not just hold data.

Builds on lesson 7 · one small project

1. Quick recall

Without looking back: what does reading a key that is not in a map return?

2. A method has a receiver

A method is a function with a special parameter — the receiver — written between func and the name. It attaches the function to a type:

func (p person) greet() string {
    return "Hello, " + p.name
}

(p person) is the receiver: every call gets its own copy of a person in p, and the body reads its fields with a dot. You call it on a value of that type: ada.greet(). Same logic as lesson 4's greet(name) — but now the data and the behavior live together, and there is no parameter to pass by hand.

3. Give lesson 6's people behavior

In your hello-go module, replace main.go with:

package main

import "fmt"

type person struct {
    name string
    age  int
}

func (p person) greet() string {
    return "Hello, " + p.name
}

func (p person) decade() string {
    return fmt.Sprint(p.name, " is in their ", p.age/10*10, "s")
}

func main() {
    people := []person{
        {name: "Ada", age: 36},
        {name: "Alan", age: 41},
    }
    for _, p := range people {
        fmt.Println(p.greet(), "-", p.decade())
    }
}
go run .

You should see Hello, Ada - Ada is in their 30s and Alan's equivalent. p.age/10*10 is integer division then multiplication — it rounds down to the decade, because int arithmetic drops fractions. Now add a method initial() string returning the first letter of the name via p.name[0:1], call it, and run again.
