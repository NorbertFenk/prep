2. Testing is built in

No framework to install. Go's go test command runs every function named TestXxx (capital T) that takes t *testing.T, in every file whose name ends in _test.go. Inside, you call the code under test and report failure through t:

if got != 5 {
    t.Errorf("divide(10, 2) = %d, want 5", got)
}

Errorf logs the failure and keeps going; Fatal logs and stops the test — use it when continuing makes no sense, like an unexpected error.

3. Test lesson 11's divide

In your hello-go module, replace main.go with:

package main

import (
    "errors"
    "fmt"
)

func divide(a, b int) (int, error) {
    if b == 0 {
        return 0, errors.New("cannot divide by zero")
    }
    return a / b, nil
}

func main() {
    result, err := divide(10, 2)
    if err != nil {
        fmt.Println("error:", err)
        return
    }
    fmt.Println(result)
}

Then create divide_test.go next to it:

package main

import "testing"

func TestDivide(t *testing.T) {
    got, err := divide(10, 2)
    if err != nil {
        t.Fatal(err)
    }
    if got != 5 {
        t.Errorf("divide(10, 2) = %d, want 5", got)
    }
}

func TestDivideByZero(t *testing.T) {
    _, err := divide(10, 0)
    if err == nil {
        t.Error("expected an error, got nil")
    }
}
go test .

You should see PASS. Add -v (go test -v .) to see each test named. Now plant a bug: change return a / b, nil to return a/b + 1, nil, run the tests, and watch TestDivide fail with your exact message — while TestDivideByZero still passes, because it tests a different path. Revert the bug.
