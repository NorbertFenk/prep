Fail on purpose, fail politely

In about ten minutes, you will return an error from a function and handle it the way nearly every line of real Go does: if err != nil.

Builds on lesson 10 · one small project

1. Quick recall

2. error is just an interface

Go has no exceptions. A function that can fail returns its failure as a value — the last result, of type error. And error is exactly what lesson 10 taught: an interface, with one method, Error() string. When all is well, the error is nil:

func divide(a, b int) (int, error) {
    if b == 0 {
        return 0, errors.New("cannot divide by zero")
    }
    return a / b, nil
}

The caller's job is one reflex, repeated everywhere in Go: check the error before using the result.

result, err := divide(10, 0)
if err != nil {
    fmt.Println("error:", err)
    return
}
fmt.Println(result)

An if can also declare variables of its own — if result, err := divide(10, 2); err != nil keeps result and err alive only inside that if.

3. A function that can fail

In your hello-go module, replace main.go with:

package main

import (
    "errors"
    "fmt"
)

func divide(a, b int) (int, error) {
    if b == 0 {
        return 0, errors.New("cannot divide by zero")
    }
    return a / b, nil
}

func main() {
    if result, err := divide(10, 2); err != nil {
        fmt.Println("error:", err)
    } else {
        fmt.Println("10 / 2 =", result)
    }

    result, err := divide(10, 0)
    if err != nil {
        fmt.Println("error:", err)
        return
    }
    fmt.Println("10 / 0 =", result)
}
go run .

You should see 10 / 2 = 5, then error: cannot divide by zero — and not a crash. Note the parenthesized import block: that is how two or more imports are written. Now change the message in errors.New, run again, and watch the caller print your new text without knowing anything changed.
