Go / Lesson 18

Your first service

In about ten minutes, you will have a web server running on your machine — a dozen lines of standard library, no frameworks, no dependencies.

Builds on lesson 17 · one small project

1. Quick recall

Without looking back: what makes greet.Hello callable from package main?

2. net/http does the hard part

Go's standard library ships a production-grade HTTP server. You supply a handler: a function taking two parameters — w http.ResponseWriter, where you write the response, and r *http.Request, everything about the request (a pointer, lesson 9). http.HandleFunc routes a path to your handler; http.ListenAndServe starts listening — and, like every good Go function, returns an error (lesson 11).

3. Run it

In your hello-go module, replace main.go with:

package main

import (
    "fmt"
    "net/http"
)

func hello(w http.ResponseWriter, r *http.Request) {
    fmt.Fprintln(w, "Hello,", r.URL.Path)
}

func main() {
    http.HandleFunc("/", hello)
    fmt.Println("listening on :8090")
    if err := http.ListenAndServe(":8090", nil); err != nil {
        fmt.Println("error:", err)
    }
}
go run .

The program prints listening on :8090 and then blocks — serving forever, one goroutine per request behind the scenes. Open a browser at http://localhost:8090/anything, or in a second terminal:

curl http://localhost:8090/ada

You should see Hello, /ada — the handler echoed the path you asked for. fmt.Fprintln(w, ...) writes into the response instead of the terminal, because w is where responses go. When you are done, stop the server with Ctrl-C: nothing ends a blocking ListenAndServe but killing it (or an error, like a second server grabbing port 8090 — try running it twice and read the error you get).
