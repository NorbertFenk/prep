Go / Lesson 9

Change the thing itself

In about ten minutes, you will use pointers — & and * — to let a method actually change a struct, not just a copy of it.

Builds on lesson 8 · one small project

1. Quick recall

Without looking back: can a method with receiver (p person) change the original struct?

2. Addresses, not copies

Every value lives at a memory address. &x gives you the address of x; *p follows a pointer p back to the value it points at:

age := 36
pointer := &age   // pointer is *int — "address of an int"
*pointer = 37     // write through the pointer
fmt.Println(age)  // 37 — age itself changed

A value receiver gets a copy, so changes die with it. A pointer receiver — (p *person) — gets the address, so changes stick:

func (p *person) birthday() {
    p.age++
}

Note what you do not write: no (*p).age inside, and no (&ada).birthday() at the call. Go applies the dot and takes the address for you automatically.

3. Make a change that lasts

In your hello-go module, replace main.go with:

package main

import "fmt"

type person struct {
    name string
    age  int
}

func (p *person) birthday() {
    p.age++
}

func main() {
    age := 36
    pointer := &age
    *pointer = 37
    fmt.Println(age)

    ada := person{name: "Ada", age: 36}
    ada.birthday()
    fmt.Println(ada.name, "is", ada.age)
}
go run .

You should see 37, then Ada is 37. Try changing the receiver to (p person), run again, and watch the second line stay at 36 — the copy took the birthday, not Ada. Change it back. Then call ada.birthday() twice and check the age.

4. Retrieve

What does &age produce?

What does *pointer = 37 do?

Why does ada.birthday() work without writing (&ada).birthday()?
