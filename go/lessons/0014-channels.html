Hand data between goroutines

In about ten minutes, you will collect results from goroutines through a channel — Go's version of "don't share memory; communicate."

Builds on lesson 13 · one small project

1. Quick recall

Without looking back: what does wg.Wait() do?

2. A channel is a typed pipe

A WaitGroup says when goroutines are done; a channel carries what they produced. Make one with make, send with ch <- value, receive with <-ch — the arrow points the way the data flows:

ch := make(chan string)
ch <- "hello"   // send into the channel
fmt.Println(<-ch) // receive out of it

An unbuffered channel is a hand-off: a send waits until some receiver takes the value, and a receive waits until some sender offers one. That waiting is the synchronization — receive three values and you know three goroutines sent, no WaitGroup needed.

3. Collect three greetings

In your hello-go module, replace main.go with:

package main

import (
    "fmt"
    "time"
)

func greet(name string, ch chan string) {
    time.Sleep(time.Duration(len(name)) * 100 * time.Millisecond)
    ch <- "Hello, " + name
}

func main() {
    names := []string{"Ada", "Grace", "Alan"}
    ch := make(chan string)
    for _, name := range names {
        go greet(name, ch)
    }
    for i := 0; i < len(names); i++ {
        fmt.Println(<-ch)
    }
}
go run .

You should see three greetings, shortest name first — each goroutine sends as soon as its sleep ends, and main prints whatever arrives next. Run it a few times, then add "Edsger" to the names and check you get four lines: the receive loop must match the number of sends, or main waits forever (or exits too early). No WaitGroup in sight — the three receives did its job.
