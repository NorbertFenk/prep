Goroutines and WaitGroups

A goroutine is a function running concurrently; a WaitGroup tracks when the ones you started have finished.

Start and wait

var wg sync.WaitGroup
for _, name := range names {
    wg.Add(1)
    go greet(name, &wg)
}
wg.Wait()
SyntaxMeaning
go f(x)Runs f(x) in a new goroutine; the caller continues immediately.
go func() { ... }()Same, with an anonymous function defined and called on the spot.
wg.Add(1)Raises the pending counter — before starting the goroutine.
defer wg.Done()Lowers the counter when the function exits, however it exits.
wg.Wait()Blocks until the counter reaches zero.

defer

defer f() schedules f to run when the surrounding function returns — the idiom for cleanup (Done(), closing files, unlocking mutexes). Stacked defers run last-in, first-out.

Gotchas

main returning ends the whole program — unfinished goroutines are abandoned, silently. Always Wait() (or receive their results) before exiting. Pass shared state by pointer (&wg) so goroutines touch the original. When goroutines write to shared data instead of a channel, guard it with a sync.Mutex.
