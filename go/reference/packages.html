Go quick reference

Your own packages

One directory = one package. Import path = module path + directory. Capital = exported.

Layout

hello-go/
├── go.mod          module example.com/hello-go
├── main.go         package main   → imports "example.com/hello-go/greet"
└── greet/
    └── greet.go    package greet
RuleMeaning
Every file starts with package XAll files in one directory share the same package name.
Import path = module path + directoryexample.com/hello-go/greet for the greet/ directory.
Call as pkg.NamePackage name (not path) prefixes every exported name — greet.Hello(...), like fmt.Println.

Exporting

NameVisible
Hello, Person, MaxRetriesEverywhere the package is imported — capital first letter.
decorate, person, maxRetriesOnly inside its own package — lowercase first letter.

There is no export keyword and no per-file visibility: case is the entire mechanism, and it applies to types, fields (see JSON), functions, and variables alike.

Conventions

Package names are short, lowercase, singular: greet, not greetUtils. package main is the executable; every other package is a library. The main package may span several files in one directory — go run . compiles them together; go run main.go compiles only that file and will miss the others.
