Closing and choosing

Two patterns that finish what goroutines and channels start: close + range, and select.

Close and range — "stream until done"

func greetAll(names []string, ch chan string) {
    for _, name := range names {
        ch <- "Hello, " + name
    }
    close(ch)          // the sender closes
}

go greetAll(names, ch)
for msg := range ch {  // ends when ch closes and drains
    fmt.Println(msg)
}
RuleWhy
Only the sender closesOnly it knows no more values are coming; receivers can't tell "quiet" from "done".
Never close twice, never send on closedBoth panic.
Close is optionalGarbage collection reclaims unclosed channels; close only when a receiver must know (range, comma-ok).
v, ok := <-chok false → channel closed and empty.

Select — "whichever is ready first"

select {
case msg := <-ch:
    fmt.Println(msg)
case <-time.After(50 * time.Millisecond):
    fmt.Println("too slow, moving on")
}
BehaviorDetail
Blocks until a case is readyThen runs exactly that one case.
Several ready at oncePicks uniformly at random — no priority.
time.After(d)A channel that receives once after d — the standard timeout idiom.
default:Runs immediately if nothing else is ready — makes select non-blocking.

Deadlock

When no goroutine can ever make progress — every one blocked on a channel — the runtime kills the program with fatal error: all goroutines are asleep - deadlock!. Common causes: forgot to close before a range; more receives than sends; unbuffered send with no receiver.
