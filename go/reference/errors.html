Go quick reference

Errors

Go has no exceptions: failures are values of type error, returned last and checked first.

The shape

SyntaxMeaning
func f() (T, error)Convention: real result first, error last.
errors.New("text")Creates an error whose Error() returns text (import errors).
fmt.Errorf("bad id %d", n)Same, with formatting (import fmt).
return v, nilSuccess: the error is nil.
if err != nil { ... }The universal check, immediately after the call.
if v, err := f(); err != nilIf with a declaration: v and err live only inside the if.

error is an interface

type error interface {
    Error() string
}

Any type with an Error() string method is an error — the same implicit satisfaction as every interface. Custom types carry structured detail:

type NotFoundError struct{ Name string }
func (e NotFoundError) Error() string { return e.Name + " not found" }

Wrapping and inspecting

SyntaxMeaning
fmt.Errorf("read config: %w", err)Wraps err with context; %w keeps the original reachable.
errors.Is(err, os.ErrNotExist)True when err is (or wraps) that specific error.
errors.As(err, &target)Extracts a wrapped error of a specific type.

panic is for unrecoverable programmer errors only — ordinary failure is always an error value.
